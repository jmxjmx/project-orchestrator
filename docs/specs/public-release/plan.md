# 公开版发布计划

## 基线

- 源仓库位于独立目录，工作区干净。
- 源仓库包含旧账号署名、旧提交历史、内部评测运行器和机器相关路径。
- 目标目录存在且为空。

## 方案

1. 通过 `git archive` 导出已跟踪文件，不复制 `.git`。
2. 删除内部评测运行器及其单元测试。
3. 删除旧发布规格和 benchmark 记录。
4. 替换 README、LICENSE 和 RELEASE_NOTES 中的旧身份和环境信息。
5. 使用动态用户目录解析替换固定 Windows 用户路径。
6. 强化 `.gitignore`，覆盖认证材料、Codex 临时目录和评测输出。
7. 初始化无远程地址的全新 Git 仓库，不创建提交。
8. 在用户确认新的 GitHub 账号并完成登录后，设置提交身份、创建公共仓库并推送 `main`。

## 副作用范围

- 仅写入目标公开目录。
- 不修改源 Skill 目录。
- 经用户明确授权，创建公共 GitHub 仓库并推送全新初始提交。

## 验证策略

- 使用文本检索检查旧账号、邮箱、用户路径、令牌和私钥模式。
- 运行仓库确定性自检。
- 校验 JSON、Markdown 链接和评测样本引用。
- 检查 Git 仓库配置中不存在旧远程地址。
- 检查公共仓库可见性、默认分支和远端提交哈希。

## 回滚

目标目录在实施前为空。需要回滚时，仅移除本次在目标目录创建的文件和 Git 元数据。
